## 실험 결과: 전체 검색 결과 전달 vs 관련 문서 선택

HotpotQA 100개 질문에서 **gpt-6-luna의 멀티 레이블 tool 예측과 멀티 스텝 ReAct**를 평가했다. 각 tool은 BM25 검색을 수행하고, 누적 검색 순위를 RRF로 결합한다.

- **ALL:** RRF로 결합한 검색 결과 전체를 다음 agent 입력에 전달한다.
- **SELECTED:** LLM이 관련 문서 인덱스를 선택하고, 선택한 문서만 다음 agent 입력에 전달한다.

두 조건은 동일한 질문을 평가하며, 전달된 context에 따라 이후 tool 선택과 검색 query가 달라질 수 있는 end-to-end 비교다.

### 답변 정확도와 실행 효율

| 지표 | ALL | SELECTED | 변화 |
|---|---:|---:|---:|
| 평가 질문 수 | 100 | 100 | — |
| 오류 수 | 1 | 0 | −1 |
| Answer EM | 22.0% | **27.0%** | +5.0%p |
| Answer F1 | 46.82% | **51.74%** | +4.92%p |
| 평균 지연 | **3.90초** | 6.06초 | +55.2% |
| 평균 총 입력 토큰 | **7,023.08** | 8,498.03 | +21.0% |
| 평균 출력 토큰 | **127.86** | 150.97 | +18.1% |
| 평균 agent 입력 토큰 | 7,023.08 | **1,192.92** | −83.0% |
| 평균 selector 입력 토큰 | 0 | 7,305.11 | 추가 호출 |
| 평균 LLM 호출 수 | **2.44** | 4.14 | +69.7% |
| 평균 검색 tool 호출 수 | **3.44** | 3.59 | +4.4% |

SELECTED는 agent 입력 토큰을 **83.0% 줄이면서 답변 EM을 5.0%p 개선**했다. 다만 selector가 검색 후보 전체를 읽으므로 **총 입력 토큰은 21.0%, 지연은 55.2% 증가**했다. 이번 구성에서 문서 선택은 정확도와 agent context 압축에 도움이 되었으며, 시스템 전체의 토큰·지연 절감으로 이어지지는 않았다.

### 멀티 레이블 tool 예측

각 실행에서 호출한 tool 레이블의 합집합을 gold supporting document가 속한 검색 shard 집합과 비교했다.

| 지표 | ALL | SELECTED |
|---|---:|---:|
| Tool-set EM | 22.0% | **25.0%** |
| Precision | 60.50% | **62.58%** |
| Recall | 88.50% | **89.00%** |
| F1 | 67.93% | **69.53%** |

SELECTED의 tool 예측 지표가 소폭 높았다. 두 조건 모두 recall이 약 89%로, 정답 근거가 있는 도구를 호출하는 비율은 높았다.

**해석상 한계:** HotpotQA에는 native tool-call 정답이 없으므로 gold tool 레이블은 근거 문서의 shard에서 파생했다. 탐색을 위해 추가 shard를 호출하는 정상 행동도 precision과 EM에서 감점된다. 따라서 이 지표는 필요한 검색 도구의 coverage를 확인하는 보조 지표로 사용한다.

### 전달 문서와 최종 인용 근거

아래 지표는 문서 title 집합 기준이며, 공식 HotpotQA의 sentence-level supporting fact 지표와 다르다.

| 평가 대상 | 지표 | ALL | SELECTED |
|---|---|---:|---:|
| 최종 agent context | EM | 0.0% | **55.0%** |
| 최종 agent context | Precision | 6.12% | **90.83%** |
| 최종 agent context | Recall | 78.50% | 78.50% |
| 최종 agent context | F1 | 11.19% | **81.82%** |
| 답변에 인용한 근거 | EM | 45.0% | **49.0%** |
| 답변에 인용한 근거 | Precision | 90.50% | **93.67%** |
| 답변에 인용한 근거 | Recall | 68.50% | **73.00%** |
| 답변에 인용한 근거 | F1 | 75.83% | **79.80%** |

SELECTED는 최종 context의 근거 recall 평균을 유지하면서 precision을 크게 높였다. 최종 인용 근거의 precision과 recall도 함께 개선되었다.

단, 두 조건의 검색 경로가 달라질 수 있으므로 **평균 context recall이 같다는 결과만으로 selector가 모든 질문에서 근거를 손실 없이 보존했다고 해석할 수는 없다.** ALL의 context EM 0%는 추가 검색 문서가 포함되어 gold 문서 집합과 정확히 일치하지 않았다는 의미다.

### 질문 유형별 성능

| 질문 유형 | 질문 수 | ALL Answer EM | SELECTED Answer EM | 변화 |
|---|---:|---:|---:|---:|
| Bridge | 83 | 25.30% (21/83) | **31.33% (26/83)** | +6.02%p |
| Comparison | 17 | 5.88% (1/17) | 5.88% (1/17) | 0.00%p |

이번 표본에서 EM 개선은 bridge 질문에서 발생했다. Comparison은 두 조건 모두 17개 중 1개만 정답이었으며, 검색 coverage와 비교 추론 실패 사례를 추가로 확인할 필요가 있다.

### Paired 비교와 결론

같은 질문의 답변 정오를 비교한 결과:

- SELECTED만 정답: **6개**
- ALL만 정답: **1개**
- Answer EM 차이: **+5.0%p**
- Paired bootstrap 95% 신뢰구간: **0.0~10.0%p**

**관련 문서 선택은 답변 정확도와 근거 집중도를 개선했지만, 추가 LLM 호출로 총 토큰과 지연이 증가했다.** 신뢰구간 하한이 0에 닿으므로 성능 우위를 확정하기에는 표본이 부족하다. 평가 수를 늘리고 반복 실행하여 개선의 안정성을 확인해야 한다.

오류는 전체 평가 분모에 포함되며, ALL의 실패 1개도 Answer EM 0으로 계산된다. EM 정규화 규칙을 변경했다면 두 조건의 저장 결과를 동일한 규칙으로 재계산한 뒤 비교해야 한다.
